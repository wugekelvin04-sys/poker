# 德州扑克胜率计算器

一个装在 iPhone 主屏幕上的德州扑克胜率计算器。选好手牌、公共牌和人数，立刻算出胜率、成牌分布和该不该跟注。

**所有计算都在手机本地完成，不发任何网络请求。** 装好之后飞行模式也能用。

线上地址：<https://wugekelvin04-sys.github.io/poker/>

## 装到 iPhone 上

1. 用 **Safari** 打开上面的网址（必须是 Safari，Chrome 不支持添加到主屏幕）
2. 点底部的「分享」按钮 → 往下滑找到 **「添加到主屏幕」** → 添加
3. 从主屏幕图标启动，是全屏的，没有地址栏和工具栏

首次打开需要联网加载一次，之后 Service Worker 会把全部资源缓存到本地，断网也能打开。

有新版本时，App 会在每次回到前台时自动检查并静默更新，更新完自动刷新一次。万一没生效，点底部那行「版本 vX · 点这里强制更新」可以清掉缓存重来。

## 怎么用

- **手牌 / 公共牌**：两张手牌和五张公共牌排在同一行，中间留了空当隔开，整个界面在 iPhone 上一屏放得下。点空卡槽，从底部弹出的 52 张牌里选。从你点的那张一路选到本区域最后一张——手牌、翻牌三张、转牌、河牌各自独立。中间那张即使已经有牌也会停一下方便顺手改，走完本区域才收起，不会窜到别的区域去。已经用掉的牌会自动置灰。点已填的卡槽可以更换或移除。
- **新一局**：牌栏右上角，一键开下一手——清掉牌、**底池归零、要跟回到一个大盲 2**，「还剩几人」恢复成桌上总人数，**位置自动顺延一格**（庄家每手顺时针挪一位），并把手牌重新盖上。旁边的「全清」只清牌，不动金额和位置。
- **位置轮转按总人数生成**：环长等于桌上人数，沿轮转方向是 庄位 → 后位 → 中位… → 前位… → 大盲 → 小盲。8 人桌有两个中位、两个前位座位，所以会在同一档连着待两手，这是对的；6 人桌正好一档一个座位。
- **藏牌**：新一局默认就是盖着的，点牌背才显示。也可以随时点右上角「隐藏」把牌盖回去，牌型和起手记号也一并遮住，桌上不怕被旁边的人瞄到。**隐藏完全不影响胜率计算**，照样实时更新。想看的时候点一下牌背就翻开。手牌本身也做得比公共牌小一圈。
- **对手水平**：决定按多强的范围给对手发牌来估胜率。**娱乐局**按随机牌算（默认）；**一般**按前 55%；**老手**按前 30%。

  **只在有人下注要你跟的时候才生效**——没人下注时大家还没做任何选择，范围本来就是随机的，这时收窄反而错。所以翻牌前没人加注、或翻牌后一圈过牌，都会自动按随机牌算，说明栏里也不会出现「按对手前 X% 估算」。这条自动切换和模拟里验证过的做法一致。

  效果很直观（K9o，老手档）：翻牌前无人加注 57.7%，一旦有人加注就掉到 41.2%；翻到 T42 上没人下注 44.7%，有人下注则只剩 24.3%。
- **共 N 人**（「还剩」那一行末尾的小框）：牌桌大小，设一次就行。「还剩」的按钮只渲染到这个数为止，新一局也会把「还剩」恢复成它。
- **还剩几人**：**还在这手牌里**的人数，含你自己，已经弃牌的不算。这一个数字同时干两件事：算胜率（对手越多胜率越低），以及推算底池。
- **当前牌型**：显示你现在的最好牌型，以及河牌发完后各种牌型的成牌概率——这就是听牌提示，比数 outs 更准。
- **坚果牌提示**：当模拟里一次都没输过（输 0%），结果区会直接标出「**坚果牌 · 不可能输**」。这时胜率往往还是不到 100%，因为公共牌本身就凑得差不多、别人也能凑出同样大的牌，要平分底池。例如 J9o 拿在 A♣8♦T♣Q♦K♥ 上是 A 高 Broadway 顺，谁也打不过，但只要有人手里也有 J 就平分——4 人桌「一般」档下 44.9% 的牌局要平分，所以胜率只有 76.6%。
- **「胜率」和「独赢」不是一回事**：大字的胜率是把平局按人头折算进去的净权益。比如独赢 17.3%、平分底池 6.1%，胜率就是 17.3 + 6.1/2 ≈ 20.2%。有平局可能时下面会写清楚这笔账。
- **成牌分布**：默认收起，点「成牌分布」展开看河牌发完后各种牌型的概率。
- **行动建议**：两个数，快捷按钮点一下就行，也可以直接输入。
  - **原底池** = 本轮下注**之前**的底池，**一整轮都不用改**。本轮投进去的钱由「已跟几人 × 要跟」自动算出来，结果里会写明算式（`底池 200（原 100 + 2×50）`）。
    快捷档 20/100/200/300/500，两侧还有加减键，步长跟着当前档位走（200 档步长 20，500 档步长 100）——想要 260 就选 200 再按三下加号。
  - **已跟几人**（含下注的那个，只在翻牌后有人下注时出现）= 已经把这笔钱投进池子的人数。**默认是「?」，不填也能算**——那时按「只有下注的人投了钱」处理，剩下的交给下注尺度去估。填了更准。

    为什么不能用「还剩几人」代替：**还剩的人里，排在你后面的那些根本还没说话**。而且这两个数一减就得出后面有几个人，不需要靠位置去猜：`后面没说话的 = 还剩 − 已跟 − 我`。
  - **要跟** = 你要跟多少（快捷档 0/2/5/10/20/30/40/50）。翻牌前填 2（一个大盲）表示还没人加注，走开池判断；填更大就是有人加到那个数了。翻牌后填 0 表示没人下注。

  - **我的筹码**（在「行动建议」标题栏里，直接输入）= 你手上还剩多少。所有建议都受它约束，超过就直接说**全下**；筹码不够跟注时，赔率也会按你实际投得进去的钱算（对手多下的部分会退还，不该算进赔率）。

  这么定义之后所需胜率就是 `要跟 / (底池 + 要跟)`，不需要再问「前面几个人跟了」——之前那版要靠 `原底池 + 跟注 × 人数` 反推底池，一旦你后面还有人没行动，就会把他们的钱也算进去，导致底池虚高、所需胜率偏低，诱你跟不该跟的牌。
  - **翻牌前没人加注**（原底池填 0）→ 这是开池决策，见下一节。此时「需跟注」填的就是一个大盲，开池加注额直接按它算：**2.5 倍大盲**（小盲位 3 倍）。所以换个级别的桌子不用改任何设置——大盲 2 就建议加到 5，大盲 10 就建议加到 25。
  - **翻牌后没人下注** → 建议过牌还是下注、下多少筹码。
  - **有人下注** → 在弃牌 / 跟注 / 加注之间给结论，并算出具体筹码数。

### 对手范围：翻牌前看起手牌，翻牌后看牌面契合度

这是整个算法里最容易错的一环，改过三版：

**第一版**只在「面对下注」时收窄范围。错在：能跟到转牌、河牌的人，早就为前面每条街付过钱了，范围在很久以前就被筛过，跟这条街有没有下注无关。→ 改成**逐街收窄**。

**第二版**一直用「起手牌排位」筛。这个错得更离谱——在低连牌面上方向是**反的**。牌面 2♥5♣6♦ 上：

| 牌型 | 全部手牌 | 筛「起手牌前 30%」后 |
|---|---|---|
| 顺子 | 1.4% | **0.0%** |
| 两对 | 2.3% | **0.0%** |
| 高牌 | 59.9% | **75.6%** |

34o 打成顺子却排在起手牌后 5% 被剔除，22 打成三条排前 48% 被剔除，而 AK 只是 A 高却因排前 5% 被留下——**筛完之后废牌反而更多了**。

**现在**：翻牌前按起手牌排位筛，**翻牌后改按「在这个牌面上有多强」筛**（含四张同花、两头顺这类强听牌，不会被当废牌剔除）。同一个牌面，新范围里顺子占 4.5%、两对 7.7%、高牌 0%。

**底池和胜率必须用同一套假设。**这里踩过一个坑：模型把后面的人算成了对手（拉低胜率），却没把他们的钱算进底池（同时拉低赔率）——**双重悲观**。既然假设有 N 个对手会跟到摊牌，就得承认其中 N−1 个会各投一笔进池。8 人桌面对满池下注，所需胜率从 33.3% 降到 20.0%，葫芦从「弃牌」变成「加注」。

**后面的人跟不跟，看注下得多大。**小注跟的人多，大注跑的人多，娱乐局的人又比老手跟得凶。跟注率 = `(0.65 − 下注尺度) × 档位系数`，尺度就是 `要跟 ÷ 底池`。还剩 8 人、只有下注者投了钱时的估算结果：

| 对手下注 | 娱乐局 | 一般 | 老手 |
|---|---|---|---|
| ¼ 池 | 4 个对手 | 3 个 | 3 个 |
| 半池 | 3 个 | 3 个 | 2 个 |
| 满池 | 2 个 | 2 个 | 2 个 |

**要区分「已经跟了的」和「还没说话的」。**这两拨人完全不同：前者已经把钱放进底池、必然跟到摊牌；后者多半会弃，而且**只有他们还会再往池子里加钱**。后面有几个人是精确算出来的：`还剩 − 已跟 − 我自己`。所以庄位面对下注时底池不会再涨，小盲位则要算上后面可能跟注的人。

**面对下注时，不是所有人都会跟到摊牌。**按「还剩几人」全员摊牌算，会系统性低估强牌——8 人桌拿葫芦会被算成 19.5% 从而建议弃牌，可你真正要打败的通常只有 1~3 个人。现在面对下注时按「下注那个人肯定跟到底，其余每人 40%」估算实际摊牌人数：8 人桌算 3 个对手，4 人桌算 2 个。同一手葫芦从 19.5% 回到 37.7%，面对满池下注由弃牌变跟注。

**筛范围要用「最后一次有人行动时看到的牌面」，不是当前牌面。**对手之所以被认为有牌，是因为他**跟过注**——而他跟注时看到的是上一条街的牌面，还没对刚翻开的这张做过任何决定。所以本街没人下注时，筛选用少一张的牌面；有人下注才用当前牌面。翻牌圈没人下注时上一条街是翻牌前，相当于不筛——实测这时算出来正好等于随机牌基线，符合直觉。

**范围只套在主动投钱的人身上。**把窄范围无差别套到每个对手，人一多就复合成荒谬的假设——8 人桌等于认定 7 个人同时拿着前 36% 的牌，而这件事的概率是 `0.36⁷ ≈ 0.08%`。实测 99 在 8♥8♣8♦ 上拿葫芦，8 人桌会被算成只有 **7.7%** 胜率（随机牌基线是 27.9%）。现在只有 1~2 个对手按窄范围处理（有人下注时 2 个，否则 1 个），其余按放宽 2.5 倍的范围。

99 拿葫芦在 8♥8♣8♦ 上（8 人桌、老手档）的完整结果：

| 局面 | 随机牌 | 无人下注 | 有人下注 |
|---|---|---|---|
| 翻牌 | 28.0% | 28.0% | 19.3% |
| 转牌 | 37.8% | 30.0% | 26.2% |
| 河牌 | 17.0% | 13.2% | 7.5% |

修之前翻牌有人下注这一格算出来是 **7.7%**——拿着葫芦却被判几乎必输。

两个「前 X%」含义完全不同，所以系数分开标定：

| 档位 | 翻牌前（起手牌） | 翻牌后（牌面契合度） |
|---|---|---|
| 娱乐局 | 100% | 85% |
| 一般 | 55% | 70% |
| 老手 | 30% | 55% |

再乘街道系数（翻牌 1.0、转牌 0.92、河牌 0.85）和**下注尺度系数**——小注范围宽、大注范围强，尺度就是 `要跟 ÷ 底池`（底池已含他的注，所以半池约 0.33、满池约 0.5）：系数 = `1.05 − 0.8 × 尺度`，夹在 0.65~1.0 之间。¼ 池下注只收窄到 89%，满池下注收窄到 65%。标定依据：河牌上「前 30%」意味着对手最弱也有一对 Q，「前 70%」意味着最弱是 A 高——真实牌局里能跟到河牌的人落在 60~70% 这个区间。

⚠️ 这些系数是按牌理拍的，**模拟器验证不了**（里面的机器人按固定规则下注，不会因牌面调整范围）。

### 翻牌后按位置折算胜率

位置为王不是句空话：同一手牌，**有位置能打出更多价值**——你后行动、信息更全，可以过牌看免费牌、可以薄价值下注、可以控池。理论里管这个叫**胜率兑现率（equity realization）**：原始胜率一样，有位置兑现得多，没位置兑现得少。

所以翻牌后的判断用的是折算后的胜率：

| 位置 | 折算系数 | 理由 |
|---|---|---|
| 庄位 | ×1.07 | 每条街都最后说话 |
| 后位 | ×1.00 | 要看庄家还在不在，算中性 |
| 前位 / 中位 / 小盲 / 大盲 | ×0.93 | 每条街都先说话 |

顶部显示的仍是原始胜率（那是事实），建议里会写明折算后的数字和原因。这个折算会在原始胜率落在**约 31%–36%**（面对半池下注时）改变结论——庄位够跟，大盲不够。

⚠️ **这一条没有经过模拟验证**：模拟器里的机器人不会利用位置优势，测不出差别。系数取自公认的扑克理论，不是实测出来的。

### 翻牌前完全不用底池赔率

翻牌前的两类决策都走起手牌范围，**不看底池、不看赔率**，所以那两行金额输入在翻牌前是隐藏的：

| 场景 | 判断依据 |
|---|---|
| 没人加注（要跟 = 一个大盲） | 起手牌排位 vs 该位置的开池范围 |
| 有人加注（要跟 > 一个大盲） | 起手牌排位 vs 该位置的防守范围 |

面对加注的防守范围（前百分之几），**按加注额连续缩放**——以标准开池 2.5BB 为基准，`缩放 = (2.5 / 加注BB数) ^ 0.76`。不用分档是因为硬台阶会让加到 4.4BB 和 4.6BB 落进完全不同的档，而同一档内加多少又完全不起作用。

| 加注到 | 3BB | 4BB | 6BB | 10BB | 25BB |
|---|---|---|---|---|---|
| 缩放 | 0.87 | 0.70 | 0.51 | 0.35 | 0.17 |

加注额直接从「要跟」读出来，不需要额外输入。基准表（面对 2.5BB 开池时）：

| 位置 | 跟注 | 再加注 |
|---|---|---|
| 前位 | 10% | 3% |
| 中位 | 14% | 4% |
| 后位 | 20% | 5% |
| 庄位 | 25% | 6% |
| 小盲 | 18% | 4% |
| 大盲 | **40%** | 4% |

大盲防守最宽是因为已经投过一个大盲、价格最好；小盲虽然也投过钱，但翻牌后全程没位置，所以反而要比大盲紧得多。再加注尺度：有位置打 3 倍，没位置打 4 倍。

**娱乐局多一条「跟注入池」**。起手牌排位是按**单挑**胜率排的，会严重低估同花连张在多人底池的价值——T9s 单挑排前 35%，但 8 人桌的胜率 17.8% 比排前 13% 的 KJo（17.7%）还高；76s 排前 64%，多人胜率却和排前 39% 的 K2s 一样。所以**「娱乐局」和「一般」**档下，够不上开池范围但**多人胜率明显高于均分**的牌（前位需 1.25 倍、后位 1.10 倍），会建议花一个大盲跟一手看翻牌。Q8s 在 8 人桌是均分的 1.29 倍 → 跟注；Q8o 只有 0.97 倍 → 弃牌。只有**「老手」**档禁掉这条，因为对好对手跛入是送钱。

**为什么翻牌前不能用赔率**：赔率里的胜率是按对手拿随机牌算的，而敢加注的人范围明显强于随机，算出来会系统性偏乐观、诱你跟太多。这一点在模拟里有明确数据（见下文）。

### 起手牌强度是怎么来的

翻牌前是否开池，**不能拿「多人全下的胜率」跟「1/人数 的均分份额」比**。真实牌局里绝大多数时候大家都弃牌了，你赢的是盲注，而全下均分这个模型里根本没有弃牌率(fold equity)这回事。按那个标尺算，同一手牌在枪口和庄位会得到一模一样的建议，这显然不对。

**而且防守和开池要用两张不同的排位表。**起手牌排位按「对随机牌的胜率」排，用来判断开不开池没问题，但拿它判断防守是错的：77 对随机牌 66.2%（排前 4.2%），对前 20% 的加注范围只剩 49.1%（掉 17 个点），而 AKo 只掉 1.7 个点。用同一张表会把 77 排在 AKo 前面，导致 77 面对 3-bet、4-bet 都建议跟注。所以 `preflop.js` 里存了两张表：`percentile` 对随机牌（判断开池），`vsRaise` 对前 20% 范围（判断防守）。按后者重排后最强的十二手是 **AA KK QQ AKs AKo JJ AQs AQo TT AJs AJo 99**，77 落到第 17 位。

翻牌前改用起手牌强度排位：`preflop.js` 里存着 169 手起手牌对 1 名随机对手的胜率（每手 50 万次模拟，由 `tools/gen-preflop.mjs` 生成），按组合数加权算出这手牌排在全部 1326 种组合的前百分之几，再对照该位置的标准开池范围（RFI）：

| 位置 | 6 人及以下 | 7 人及以上 |
|---|---|---|
| 前位 | 16% | 11% |
| 中位 | 21% | 16% |
| 后位 | 28% | 24% |
| 庄位 | 45% | 42% |
| 小盲 | 42% | 40% |

判断「有没有人加注」看的是**原底池是不是 0**，不是拿需跟注去比某个写死的数字——那样换级别的桌子就整个失灵了。真有人加注时死钱必然大于 0，否则底池赔率本身也算不对。

**位置要显式选，不能用「后面还有几人」推算**——翻牌前盲注是在庄家之后行动的，按人数推会把庄位算成还有两人未行动、判成很紧的范围，而实际庄位开得最宽。大盲单独处理：没人加注就是免费看翻牌，直接过牌。

这套排位是纯胜率口径，会低估口袋对子和同花连张的实战价值（它们的价值在于摸暗三和成同花后的隐含赔率）。所以面对加注被判弃牌时，如果手上是口袋对子，会额外提示隐含赔率——翻牌摸中暗三约 12%，手上筹码够跟注额 15 倍以上就值得摸一手。另外翻牌前对手主动下注说明他的范围强于随机牌，而胜率是按随机牌算的，界面上也会提醒实战胜率比显示的更低。判断依据是胜率、底池赔率和人数对应的公平份额——**这是个粗略的经验规则，没有考虑位置、对手风格和后续街的可玩性**，别当 GTO 用。

## 算法

`engine.js` 是牌力评估器。牌用 0–51 的整数表示（`rank = c >> 2`，`suit = c & 3`），评估结果是一个 32 位整数（`牌型等级 << 20 | 五张关键牌打包`），同类型之间直接用 `>` 比大小。核心是三张 8192 项的查找表（popcount、最高顺子、最高五张），配合位运算，单次评估约 0.3 微秒。支持 2–7 张任意数量。

`sim.js` 是蒙特卡洛模拟。每轮从剩余牌堆做部分 Fisher-Yates 洗牌，发给对手并补齐公共牌，比较分值统计胜/平/负；平局按并列人数分摊权益。默认跑 25 万次或 1.6 秒（取先到者），误差约 ±0.2%，结果里带 95% 置信区间。

摊牌单挑（公共牌 5 张 + 2 人）时未知组合只有 C(45,2)=990 种，直接**精确枚举**，零误差。

计算全部在 Web Worker 里跑，界面不会卡。少数浏览器创建不了 Worker（或 worker 脚本加载失败、迟迟没有响应），这时会自动退回主线程，把模拟切成每片 1 万次轮流执行，同样能跑满次数而不僵住界面，说明栏里会标注「主线程」。

## 验证

```bash
node test/engine.test.mjs    # 40 项牌型与踢脚比较的单元测试
node test/validate.mjs       # 数值验证，约 1 分钟
```

`validate.mjs` 做了四件事：

1. **枚举全部 C(52,5) = 2,598,960 手牌**，各牌型频数必须精确等于公认值（同花顺 40、四条 624、葫芦 3744、同花 5108、顺子 10200、三条 54912、两对 123552、一对 1098240、高牌 1302540），且不同分值恰好 **7462** 个——这是德州扑克 5 张牌的等价类数量，能同时证明踢脚打包既无碰撞也没有制造出虚假区分。
2. **精确枚举 vs 蒙特卡洛**：河牌单挑（990 种）和翻牌单挑（1,070,190 种）各跑一遍精确枚举，与模拟结果比对，偏差须小于 0.5%，用于证明采样无偏。
3. **对照公认翻牌前胜率**：AA 85.2%、AKs 67.0%、72o 34.6%、KK 82.3%、AA 对 8 家 34.6%、AA 对 9 家 31.1%，全部吻合到 0.12% 以内。
4. 一致性：胜/平/负相加为 1，牌型分布相加为 1，胜率随人数单调下降。

## 这套算法到底赚不赚钱

`tools/sim-session.mjs` 是一个完整的 8 人无限注德州模拟器（含边池、每街封顶四次加注），让本 App 的决策规则真刀真枪打 10 万手。盲注 1/2，每人 200（100BB），每手结束把盈亏收走再坐回 200——不这么做的话赢家筹码会无限滚雪球，量出来的就成了滚雪球效应而不是策略好坏。

```bash
node tools/sim-session.mjs 100000 mixed algo     # 混合桌，用本 App 算法
node tools/sim-session.mjs 100000 tag tag        # 对照：换成简单紧凶规则
node tools/sim-session.mjs 100000 mirror         # 公平性自检：全桌同一算法
```

先过公平性自检：8 个座位都用同一套算法时，各座位落在 −4.8 ~ +5.2 BB/100、合计为 0，属于纯方差，引擎没有偏向。

10 万手结果（BB/100 = 每 100 手赢多少个大盲）：

| 对手 | 本 App 算法 | 简单紧凶规则（对照） |
|---|---|---|
| 混合桌（2 跟注站 + 3 松被动 + 2 紧凶） | **+163.6** | +63.1 |
| 全松被动 | +146.9 | +42.3 |
| 全跟注站 | +509.9 | +111.9 |
| **全紧凶** | **+5.6** | **+10.5** |

三个结论：

1. **对手越松，这套算法赚得越多，而且明显强于简单的紧凶规则。**赔率和胜率的账算清楚，确实能从爱跟注的人身上多榨出一截。
2. **对手一旦纪律严明，它就打不过一个简单的紧凶规则**（+5.6 对 +10.5）。换成会弃牌也会偷鸡的对手（`pro`），现版本更是直接亏钱：**−28.5 BB/100**。原因正是界面上标注过的那条局限：**胜率是按随机牌算的**。好对手只在范围强的时候投钱，算出来的胜率就系统性偏乐观，于是跟得太多。
3. **「对手水平」这个开关就是为此而加的。**把对手范围收窄到前 30% 之后，同样面对 `pro` 从 −28.5 变成 **+26.2**，反超简单紧凶规则的 +18.0。但对松散对手不能这么干——跟注站真的什么烂牌都下注，收窄范围会让你白白弃掉好牌（+510 掉到 +382）。所以这个设置默认是「娱乐局」，遇到硬桌子再切。

试过但**没有采纳**的几条，都有实测支撑：

| 改动 | 对手=高手 | 混合桌 | 结论 |
|---|---|---|---|
| 「临界」判为弃牌 | +3.4（原 +6.7） | +131.6（原 +187.4） | 两边都变差 |
| 25% 频率半诈唬 | −14.8 | +163.5 | 变差 |
| 30% 频率抓偷鸡 | −14.7 | +133.0 | 变差 |
| 留一个对手（大盲）不受范围限制 | −5.8（原 +15.8） | +120.6 | 明显变差 |

诈唬和抓偷鸡那两行要打个折扣看：这些机器人不会弃牌也不会偷鸡，等于只出石头就宣布布没用，测不准。留出盲注那条则是真的更差——面对下注做决策时，下注的人是自愿投钱的，把其中一个当随机牌等于把刚修正掉的乐观偏差又加回来；而大盲范围宽这件事主要发生在翻牌前无人加注，那个场景本来就不用胜率判断。

**这些数字不要当真去对标实战。**这些机器人不会诈唬、不会调整、不看位置、拿到一对就不肯弃牌，比真实的差牌手还要差得多。真实牌局还有抽水——现金桌抽水通常在 5–10 BB/100，光这一项就足以把面对好对手的那点优势吃干净。把这张表当成**排序**看（对松散对手算法更强、对严谨对手算法更弱），别当成收益预测。

## 本地开发

```bash
python3 -m http.server 8777      # Service Worker 需要 http，不能用 file://
open http://localhost:8777/
node tools/make-icons.mjs        # 重新生成图标（需要本机装了 Chrome）
```

改了文件之后**必须**统一升版本号：

```bash
node tools/set-version.mjs v8
```

它会同时改掉 `index.html` 里所有资源的 `?v=` 查询串、`sw.js` 的缓存名和 `app.js` 的显示版本。三者必须完全一致——否则会出现「新 HTML 配旧 JS」，页面直接白掉。

缓存策略也是围绕这点设计的：页面本身走**网络优先**（联网必拿最新 HTML，断网回落缓存），子资源走缓存优先但**按完整 URL 匹配**（不能 `ignoreSearch`，否则 `app.js?v=v8` 会命中旧的 `app.js?v=v7`）。另外 `index.html` 末尾有一段自愈脚本：若 1.8 秒内 `window.__APP_OK` 没被置上，说明初始化失败，会自动清缓存并重载一次。
