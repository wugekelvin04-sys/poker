# 德州扑克胜率计算器

一个装在 iPhone 主屏幕上的德州扑克胜率计算器。选好手牌、公共牌和人数，立刻算出胜率、成牌分布和该不该跟注。

**所有计算都在手机本地完成，不发任何网络请求。** 装好之后飞行模式也能用。

线上地址：<https://wugekelvin04-sys.github.io/poker/>

## 装到 iPhone 上

1. 用 **Safari** 打开上面的网址（必须是 Safari，Chrome 不支持添加到主屏幕）
2. 点底部的「分享」按钮 → 往下滑找到 **「添加到主屏幕」** → 添加
3. 从主屏幕图标启动，是全屏的，没有地址栏和工具栏

首次打开需要联网加载一次，之后 Service Worker 会把全部资源缓存到本地，断网也能打开。

有新版本时，App 会在每次回到前台时自动检查并静默更新，更新完自动刷新一次。万一没生效，点底部那行「版本 vX · 点这里强制更新」可以清掉缓存重来。

## 怎么用

- **手牌 / 公共牌**：两张手牌和五张公共牌排在同一行，中间留了空当隔开，整个界面在 iPhone 上一屏放得下。点空卡槽，从底部弹出的 52 张牌里选。选完会自动跳到**同一区域**里的下一张，连着点就行——手牌、翻牌三张、转牌、河牌各自独立，选完当前区域就收起，不会窜到别的区域去。已经用掉的牌会自动置灰。点已填的卡槽可以更换或移除。
- **新一局**：牌栏右上角，一键清掉手牌、公共牌和这一手的金额，人数和位置留着不动。
- **藏牌**：手牌那一栏右上角有「隐藏」，点一下自己的两张牌变成牌背，牌型和起手记号也一并遮住，桌上不怕被旁边的人瞄到。**隐藏完全不影响胜率计算**，照样实时更新。想看的时候点一下牌背就翻开。手牌本身也做得比公共牌小一圈。
- **还剩几人**：**还在这手牌里**的人数，含你自己，已经弃牌的不算。这一个数字同时干两件事：算胜率（对手越多胜率越低），以及推算底池。
- **当前牌型**：显示你现在的最好牌型，以及河牌发完后各种牌型的成牌概率——这就是听牌提示，比数 outs 更准。
- **「胜率」和「独赢」不是一回事**：大字的胜率是把平局按人头折算进去的净权益。比如独赢 17.3%、平分底池 6.1%，胜率就是 17.3 + 6.1/2 ≈ 20.2%。有平局可能时下面会写清楚这笔账。
- **成牌分布**：默认收起，点「成牌分布」展开看河牌发完后各种牌型的概率。
- **行动建议**：牌桌上心算底池容易出错，所以不用你填底池总额——只填「他们下注**之前**的底池」和「你要跟多少」，实际底池按 `原底池 + 跟注 × (还剩几人 − 1)` 自己算出来，并把算式写在结果里给你核对。
  - **翻牌前没人加注** → 这是开池决策，见下一节。
  - **翻牌后没人下注** → 建议过牌还是下注、下多少筹码。
  - **有人下注** → 在弃牌 / 跟注 / 加注之间给结论，并算出具体筹码数。

### 翻牌前为什么不用胜率判断

翻牌前是否开池，**不能拿「多人全下的胜率」跟「1/人数 的均分份额」比**。真实牌局里绝大多数时候大家都弃牌了，你赢的是盲注，而全下均分这个模型里根本没有弃牌率(fold equity)这回事。按那个标尺算，同一手牌在枪口和庄位会得到一模一样的建议，这显然不对。

所以翻牌前改用起手牌强度排位：`preflop.js` 里存着 169 手起手牌对 1 名随机对手的胜率（每手 50 万次模拟，由 `tools/gen-preflop.mjs` 生成），按组合数加权算出这手牌排在全部 1326 种组合的前百分之几，再对照该位置的标准开池范围（RFI）：

| 位置 | 6 人及以下 | 7 人及以上 |
|---|---|---|
| 前位 | 16% | 11% |
| 中位 | 21% | 16% |
| 后位 | 28% | 24% |
| 庄位 | 45% | 42% |
| 小盲 | 42% | 40% |

**位置要显式选，不能用「后面还有几人」推算**——翻牌前盲注是在庄家之后行动的，按人数推会把庄位算成还有两人未行动、判成很紧的范围，而实际庄位开得最宽。大盲单独处理：没人加注就是免费看翻牌，直接过牌。

这套排位是纯胜率口径，会低估口袋对子和同花连张的实战价值（它们的价值在于摸暗三和成同花后的隐含赔率）。所以面对加注被判弃牌时，如果手上是口袋对子，会额外提示隐含赔率——翻牌摸中暗三约 12%，手上筹码够跟注额 15 倍以上就值得摸一手。另外翻牌前对手主动下注说明他的范围强于随机牌，而胜率是按随机牌算的，界面上也会提醒实战胜率比显示的更低。判断依据是胜率、底池赔率和人数对应的公平份额——**这是个粗略的经验规则，没有考虑位置、对手风格和后续街的可玩性**，别当 GTO 用。

## 算法

`engine.js` 是牌力评估器。牌用 0–51 的整数表示（`rank = c >> 2`，`suit = c & 3`），评估结果是一个 32 位整数（`牌型等级 << 20 | 五张关键牌打包`），同类型之间直接用 `>` 比大小。核心是三张 8192 项的查找表（popcount、最高顺子、最高五张），配合位运算，单次评估约 0.3 微秒。支持 2–7 张任意数量。

`sim.js` 是蒙特卡洛模拟。每轮从剩余牌堆做部分 Fisher-Yates 洗牌，发给对手并补齐公共牌，比较分值统计胜/平/负；平局按并列人数分摊权益。默认跑 25 万次或 1.6 秒（取先到者），误差约 ±0.2%，结果里带 95% 置信区间。

摊牌单挑（公共牌 5 张 + 2 人）时未知组合只有 C(45,2)=990 种，直接**精确枚举**，零误差。

计算全部在 Web Worker 里跑，界面不会卡。少数浏览器创建不了 Worker（或 worker 脚本加载失败、迟迟没有响应），这时会自动退回主线程，把模拟切成每片 1 万次轮流执行，同样能跑满次数而不僵住界面，说明栏里会标注「主线程」。

## 验证

```bash
node test/engine.test.mjs    # 40 项牌型与踢脚比较的单元测试
node test/validate.mjs       # 数值验证，约 1 分钟
```

`validate.mjs` 做了四件事：

1. **枚举全部 C(52,5) = 2,598,960 手牌**，各牌型频数必须精确等于公认值（同花顺 40、四条 624、葫芦 3744、同花 5108、顺子 10200、三条 54912、两对 123552、一对 1098240、高牌 1302540），且不同分值恰好 **7462** 个——这是德州扑克 5 张牌的等价类数量，能同时证明踢脚打包既无碰撞也没有制造出虚假区分。
2. **精确枚举 vs 蒙特卡洛**：河牌单挑（990 种）和翻牌单挑（1,070,190 种）各跑一遍精确枚举，与模拟结果比对，偏差须小于 0.5%，用于证明采样无偏。
3. **对照公认翻牌前胜率**：AA 85.2%、AKs 67.0%、72o 34.6%、KK 82.3%、AA 对 8 家 34.6%、AA 对 9 家 31.1%，全部吻合到 0.12% 以内。
4. 一致性：胜/平/负相加为 1，牌型分布相加为 1，胜率随人数单调下降。

## 本地开发

```bash
python3 -m http.server 8777      # Service Worker 需要 http，不能用 file://
open http://localhost:8777/
node tools/make-icons.mjs        # 重新生成图标（需要本机装了 Chrome）
```

改了文件之后**必须**统一升版本号：

```bash
node tools/set-version.mjs v8
```

它会同时改掉 `index.html` 里所有资源的 `?v=` 查询串、`sw.js` 的缓存名和 `app.js` 的显示版本。三者必须完全一致——否则会出现「新 HTML 配旧 JS」，页面直接白掉。

缓存策略也是围绕这点设计的：页面本身走**网络优先**（联网必拿最新 HTML，断网回落缓存），子资源走缓存优先但**按完整 URL 匹配**（不能 `ignoreSearch`，否则 `app.js?v=v8` 会命中旧的 `app.js?v=v7`）。另外 `index.html` 末尾有一段自愈脚本：若 1.8 秒内 `window.__APP_OK` 没被置上，说明初始化失败，会自动清缓存并重载一次。

## 文件

| 文件 | 作用 |
|---|---|
| `engine.js` | 牌力评估，查找表 + 位运算 |
| `sim.js` | 蒙特卡洛模拟与精确枚举 |
| `preflop.js` | 169 手起手牌的强度百分位表 |
| `tools/gen-preflop.mjs` | 生成上表 |
| `worker.js` | Web Worker 入口 |
| `app.js` | 界面状态与交互 |
| `sw.js` | Service Worker，离线缓存 |
| `tools/make-icons.mjs` | 用 headless Chrome 把 SVG 渲染成 PNG 图标 |

无框架、无依赖、无构建步骤，源文件直接托管。
