# 德州扑克胜率计算器

一个装在 iPhone 主屏幕上的德州扑克胜率计算器。选好手牌、公共牌和人数，立刻算出胜率、成牌分布和该不该跟注。

**所有计算都在手机本地完成，不发任何网络请求。** 装好之后飞行模式也能用。

线上地址：<https://wugekelvin04-sys.github.io/poker/>

## 装到 iPhone 上

1. 用 **Safari** 打开上面的网址（必须是 Safari，Chrome 不支持添加到主屏幕）
2. 点底部的「分享」按钮 → 往下滑找到 **「添加到主屏幕」** → 添加
3. 从主屏幕图标启动，是全屏的，没有地址栏和工具栏

首次打开需要联网加载一次，之后 Service Worker 会把全部资源缓存到本地，断网也能打开。

有新版本时，App 会在每次回到前台时自动检查并静默更新，更新完自动刷新一次。万一没生效，点底部那行「版本 vX · 点这里强制更新」可以清掉缓存重来。

## 怎么用

- **手牌 / 公共牌**：两张手牌和五张公共牌排在同一行，中间留了空当隔开，整个界面在 iPhone 上一屏放得下。点空卡槽，从底部弹出的 52 张牌里选。从你点的那张一路选到本区域最后一张——手牌、翻牌三张、转牌、河牌各自独立。中间那张即使已经有牌也会停一下方便顺手改，走完本区域才收起，不会窜到别的区域去。已经用掉的牌会自动置灰。点已填的卡槽可以更换或移除。
- **新一局**：页面最底部一整行的大按钮——每手都要点，放在拇指最容易够到的地方。一键开下一手——清掉牌、**底池归零、要跟回到一个大盲 2**，「还剩几人」恢复成桌上总人数，**位置自动顺延一格**（庄家每手顺时针挪一位），并把手牌重新盖上。旁边的「全清」只清牌，不动金额和位置。
- **位置轮转按总人数生成**：环长等于桌上人数，沿轮转方向是 庄位 → 后位 → 中位… → 前位… → 大盲 → 小盲。8 人桌有两个中位、两个前位座位，所以会在同一档连着待两手，这是对的；6 人桌正好一档一个座位。
- **藏牌**：新一局默认就是盖着的，点牌背才显示。也可以**点「当前牌型」那一块**盖回去——一只手就能操作，牌型和起手记号也一并遮住，桌上不怕被旁边的人瞄到。**隐藏完全不影响胜率计算**，照样实时更新。想看的时候点一下牌背就翻开。手牌本身也做得比公共牌小一圈。
「对手水平」放在「我的胜率」右上角；**要在牌局中反复调的东西全部集中在「行动建议」面板**——我的位置、还剩几人、已跟几人、底池、要跟，从上到下一条线。四行的 **+/− 抽成独立一列钉在最左边**，像素级对齐，牌桌上盲按也能按到。

- **对手水平**（在「我的胜率」右上角）：这是全 App 影响面最大的一个开关，**同时改变对手范围、防守宽度、跟注人数估计**——完整对照见《算法详解》第 6 节。默认「娱乐局」。

  **范围收窄只在有人下注要你跟的时候才生效**——没人下注时大家还没做任何选择，范围本来就接近随机，这时收窄反而错。
- **共 N 人**（「还剩」那一行末尾的小框）：牌桌大小，设一次就行。「还剩」的按钮只渲染到这个数为止，新一局也会把「还剩」恢复成它。
- **还剩几人**：**还在这手牌里**的人数，含你自己，已经弃牌的不算。末尾有个 **−1** 键——牌局里人只会越来越少，有人弃牌点一下就行，不用去找数字。这一个数字同时干两件事：算胜率（对手越多胜率越低），以及推算底池。
- **当前牌型**：显示你现在的最好牌型，以及河牌发完后各种牌型的成牌概率——这就是听牌提示，比数 outs 更准。
- **坚果牌提示**：当模拟里一次都没输过（输 0%），结果区会直接标出「**坚果牌 · 不可能输**」。这时胜率往往还是不到 100%，因为公共牌本身就凑得差不多、别人也能凑出同样大的牌，要平分底池。例如 J9o 拿在 A♣8♦T♣Q♦K♥ 上是 A 高 Broadway 顺，谁也打不过，但只要有人手里也有 J 就平分——4 人桌「一般」档下 44.9% 的牌局要平分，所以胜率只有 76.6%。
- **「胜率」和「独赢」不是一回事**：大字的胜率是把平局按人头折算进去的净权益。比如独赢 17.3%、平分底池 6.1%，胜率就是 17.3 + 6.1/2 ≈ 20.2%。有平局可能时下面会写清楚这笔账。
- **成牌分布**：常显，排在「当前牌型」右侧，固定列出全部九种牌型并带比例条。**整个界面高度是完全固定的**——切换人数、藏牌、发牌、建议变化都不会让页面上下跳；用不到的输入行是置灰而不是隐藏，手指不用重新找位置。
- **行动建议**：两个数，快捷按钮点一下就行，也可以直接输入。
  - **原底池** = 本轮下注**之前**的底池，**一整轮都不用改**。本轮投进去的钱由「已跟几人 × 要跟」自动算出来，结果里会写明算式（`底池 200（原 100 + 2×50）`）。
    快捷档 20/100/200/300/500，两侧加减键的步长跟着当前档位走（20 档 ±10，100/200 档 ±20，300 档 ±50，500 档 ±100）——想要 260 就选 200 再按三下加号。
  - **要跟** 快捷档翻牌前是 0/2/5/10/20/50/100/200，翻牌后撤掉 2（没人下 2 块）换成 200。加减键沿梯子走：翻牌前 0→2→5，翻牌后 0→5，之后进入按档位的可变步长（100→200 每步 20，200 以上每步 50）。减号能一路退回 0——「过牌到我」是最常用的状态。
  - **已跟几人**（紧挨着「还剩几人」，用不到时置灰而不隐藏，位置永远不动）末尾有个 **+1** 键——一轮里跟注的人只会越来越多。= 已经把这笔钱投进池子的人数。**默认是「?」，不填也能算**——那时按「只有下注的人投了钱」处理，剩下的交给下注尺度去估。填了更准。

    为什么不能用「还剩几人」代替：**还剩的人里，排在你后面的那些根本还没说话**。而且这两个数一减就得出后面有几个人，不需要靠位置去猜：`后面没说话的 = 还剩 − 已跟 − 我`。
  - 翻牌前「要跟」填 2（一个大盲）表示还没人加注，走开池判断；填更大就是有人加到那个数了。翻牌后填 0 表示没人下注。
  - **被加注**（「要跟」那行下面的小按钮）：**他是主动下注，还是把我的注加了上去？** 这是全 App 唯一一个算法自己推不出来的信息——同样显示「要跟 30」，主动下注和加注我背后的牌力天差地别，而底池和要跟这两个数字一模一样。打开它，对手范围直接封顶到前 12%（老手档前 6%），顶对会从「加注」降级成「跟注」，第二对会从「跟注」变成「弃牌」，坚果牌不受影响。**换街和新一局自动清掉**，没人下注时置灰。

  - **我的筹码**（在「行动建议」标题栏里，直接输入）= 你手上还剩多少。所有建议都受它约束，超过就直接说**全下**；筹码不够跟注时，赔率也会按你实际投得进去的钱算（对手多下的部分会退还，不该算进赔率）。

  这么定义之后所需胜率就是 `要跟 / (底池 + 要跟)`，不需要再问「前面几个人跟了」——之前那版要靠 `原底池 + 跟注 × 人数` 反推底池，一旦你后面还有人没行动，就会把他们的钱也算进去，导致底池虚高、所需胜率偏低，诱你跟不该跟的牌。
  - **翻牌前没人加注**（原底池填 0）→ 这是开池决策，见下一节。此时「需跟注」填的就是一个大盲，开池加注额直接按它算：**2.5 倍大盲**（小盲位 3 倍）。所以换个级别的桌子不用改任何设置——大盲 2 就建议加到 5，大盲 10 就建议加到 25。
  - **翻牌后没人下注** → 建议过牌还是下注、下多少筹码。
  - **有人下注** → 在弃牌 / 跟注 / 加注之间给结论，并算出具体筹码数。

# 算法详解

下面是这套算法的完整规格。所有可调参数都写在 `strategy.js` 顶部，改一个数就能调整策略，`app.js`（手机界面）和 `tools/sim-session.mjs`（几十万手的验证模拟器）共用这同一份代码。

> 这一点很重要：早先两边各写了一份决策逻辑、注释里写着「镜像 app.js」，实际漂移了好几个版本——模拟器还在用「对随机牌的胜率 + 底池赔率」判断翻牌前要不要跟，而 App 早已改成查防守范围表。**所有「算法赚不赚钱」的结论量的都是一个不存在的策略。** 抽成一份之后这类漂移不可能再发生。

## 0. 一次计算走过哪些步骤

```
你填的东西
  手牌 / 公共牌 / 我的位置 / 还剩几人 / 已跟几人 / 底池 / 要跟 / 我的筹码 / 对手水平
        │
        ▼
① 判断局面        有没有人加注？现在是第几条街？
        │
        ▼
② 推算摊牌人数     还剩几人 − 已跟 − 我 = 后面没说话的
                  他们里有多大比例会跟（按加注尺寸和对手档位）
        │
        ▼
③ 推算对手范围     基础宽度（对手档位）× 街次系数 × 下注尺度系数
        │
        ▼
④ 蒙特卡洛        只从这个范围里给对手发牌，跑 25 万次
        │
        ▼
⑤ 位置折算        乘上胜率兑现系数（有位置打得出更多价值）
        │
        ▼
⑥ 走决策树        翻牌前查范围表 / 翻牌后算底池赔率
        │
        ▼
   弃牌 / 跟注 / 加注到 N / 下注 N / 过牌
```

第 ①②③ 步是「读局面」，第 ⑥ 步是「做决定」，中间的 ④⑤ 是纯计算。**这套算法的全部主观判断都集中在 ②③⑥ 的参数里**，下面逐个展开。

## 1. 牌力评估（`engine.js`）

牌用 0–51 的整数表示：`rank = c >> 2`（0=2 … 12=A），`suit = c & 3`。

评估结果是一个 32 位整数：

```
分值 = 牌型等级 << 20 | 五张关键牌打包（每张 4 位）
```

同类型之间直接用 `>` 比大小，不需要逐项比较踢脚。核心是三张 8192 项的查找表（13 位 rank 掩码 → popcount / 最高顺子顶张 / 最高五张打包），全部位运算，单次评估约 **0.3 微秒**。支持 2–7 张任意数量（翻牌前也能显示当前牌型）。

轮子顺 A-2-3-4-5 的顶张按 5 算，同花顺检测在该花色的掩码里查顺子表。

## 2. 蒙特卡洛与范围筛选（`sim.js`）

### 2.1 基本循环

每轮从剩余牌堆做**部分 Fisher-Yates 洗牌**（只洗出需要的前若干张），发给对手并补齐公共牌，比较分值统计胜/平/负；平局按并列人数分摊权益。默认跑 25 万次或 1.6 秒（取先到者），误差约 ±0.2%。

**河牌单挑**（公共牌 5 张 + 2 人）时未知组合只有 C(45,2) = 990 种，直接精确枚举，零误差。

### 2.2 小数人头

「后面还会跟几个」本来就是个期望值。硬取整会造成整整一个人的跳变，而少一个对手值好几个胜率点——比范围收紧的影响还大，于是会出现「选『一般』反而比『娱乐局』算出更高的胜率」这种反常。

引擎支持小数人数：`players = 3.57` 表示最边缘的那个对手**按 57% 的概率**参加这一局，多局平均下来就是 3.57 人。

### 2.3 固定随机种子

种子由局面派生（手牌 + 公共牌 + 摊牌人数 + 各项范围参数的 FNV 哈希），**同一个局面每次算出同一个数**。

不这么做的话，切换「对手水平」时两次各自 ±0.15% 的抽样抖动会叠在一起，偶尔盖过档位本身的差距。

### 2.4 两种范围筛（这是整套算法最核心的部分）

对手不是拿随机牌——他敢投钱，他的牌就强于随机。但「强在哪」翻牌前和翻牌后完全不同：

| | 用什么筛 | 参数 |
|---|---|---|
| **翻牌前** | 起手牌强度排位 | `oppMaxPctl` |
| **翻牌后** | 和当前牌面的契合度 | `oppBoardTop` |

**为什么翻牌后不能继续用起手牌排位**：牌面 2♦5♣6♥ 上，34 是接近坚果的顺子，而 AKo 什么都不是。按起手牌排位筛会把 AK 留下、把 34 删掉，完全筛反了。

#### 牌面契合度怎么算（`boardStrength`）

把对手的两张牌和当前牌面合起来评估，得到成牌分值。还有牌要发时，**强听牌不能当废牌筛掉**：

| 听牌类型 | 折算成 | 理由 |
|---|---|---|
| 同花听 + 两头顺（双听） | 两对 | 到河牌约 54% |
| 同花听 | 一对 K | 到河牌约 35% |
| 两头顺 / 双肚顺 | 一对 T | 到河牌约 32% |

听牌必须**用到至少一张底牌**——公共牌自己凑出四张同花、对手一张都没有时，那不是他在听。

> 这里踩过一个很贵的坑：原来的写法是 `if (draw) sc = PAIR_FLOOR`，直接赋值。而 `PAIR_FLOOR` 是「一对」这一档的**最低分**，真正的一对都是 `PAIR_FLOOR + 踢脚`。结果同花听在排序里**比最烂的一对还低**，范围一收紧就把对手的听牌全删光，对手再也追不上你，你的胜率反而涨。随机局面抽查，「越紧胜率反而越高」的比例从 10.5% 降到 2.9%。

#### 分两组发牌

```
oppStrong    用窄范围的对手数：有人下注时 2 个，没人下注时 1 个
oppWideTop   其余对手的宽范围 = min(1, 窄范围 × 2.5)
```

只有「这条街主动下注」的人才真的看着当前牌面做过决定，才配用当前牌面筛。剩下的人是跟着看牌的，范围明显更宽。

#### 用哪个牌面筛（`oppFilterLen`）

**本街有人下注就用当前牌面；没人下注就用少一张的牌面。**

转牌刚翻开、还没人行动时，所有人的范围只反映他们在翻牌上的决定——拿转牌那张去筛是把还没发生的决策算了进去。

#### 一个必须留住的兜底

翻牌无人下注时，筛选牌面退回两张，**牌面筛跑不起来**。这时如果起手牌筛也关掉，对手范围就退化成完全随机牌，胜率被系统性高估，于是拿底对也去下半池。所以两个筛至少留一个：

```js
oppMaxPctl: (公共牌 >= 3 && 筛选牌面 >= 3) ? 1 : activePctl(g)
```

## 3. 起手牌排位表（`preflop.js`）

**两张表，缺一不可**：

| 表 | 含义 | 用在哪 |
|---|---|---|
| `percentile` | 对**随机牌**的胜率排位 | 开池决策（对手还没做任何选择，手里就是随机牌） |
| `vsRaise` | 对**前 20% 加注范围**的胜率排位 | 面对加注（他已经亮了态度） |

界面上分别写成「**对随机牌前 35%**」和「**对加注范围前 30.6%**」，不会混。

为什么必须分两张，看 **77**：

| | 对随机牌 | 对前 20% 范围 |
|---|---|---|
| 胜率 | 66% | 49% |
| 排位 | 前 4.2% | 前 8.7% |

用错表会把 77 排在 AKo 前面，面对 3-bet、4-bet 都建议跟注。

反过来 **J8s** 是另一个方向：对随机牌前 35%，对加注范围反而前 30.6%——同花连张靠中牌取胜，不靠高牌大小，面对强范围反而相对更抗打。

## 4. 局面参数：从你填的几个数推出什么

### 4.1 有没有人加注

```js
翻牌前：要跟 + 我已投的 > 一个大盲
翻牌后：要跟 > 0
```

**翻牌前必须加上「我已投的」**，因为「要跟」是我还要补多少，只有在我没投过钱时才等于他加到多少：

| 位置 | 已投 | 无人加注时「要跟」 | 加到 4 时「要跟」 |
|---|---|---|---|
| 大盲 | 2 | 0 | 2 |
| 小盲 | 1 | 1 | 3 |
| 其他 | 0 | 2 | 4 |

三种无加注情形加起来都恰好等于一个大盲，任何人加到 4 都会被正确识别。

> 用「要跟 > 大盲」判断会出严重 bug：大盲位面对最小加注到 4 时只需补 2，`2 > 2` 不成立 → 判成「没人加注」→ 走进「大盲免费看翻牌」分支输出**过牌**。而过牌根本不是合法选项，你欠着 2 块。实测拿 **AA** 也建议过牌——任意两张牌最小加注就能白偷这个大盲。

### 4.2 摊牌人数（`showdownPlayers`）

```
后面还没说话的 = 还剩几人 − 已跟几人 − 我        ← 精确算术，不靠位置猜
摊牌人数       = 已跟的 + 后面会跟的 + 下注者 + 我
后面会跟的     = 后面没说话的 × 跟注率
```

**跟注率翻牌前后用两把完全不同的尺子：**

**翻牌后**用「要跟 ÷ 底池」：

```
跟注率 = clamp((0.65 − 要跟÷底池) × 档位系数, 0.05, 0.75)
档位系数：娱乐局 1.3 / 一般 1.0 / 老手 0.75
```

**翻牌前**改用「他加到了几个大盲」：

```
跟注率 = clamp(系数 ÷ 加注BB数, 0.02, 0.95)
系数：娱乐局 2.4 / 一般 0.85 / 老手 0.42
```

> 翻牌前的底池就只有两个盲注（1.5BB），任何正常加注除以它都大于 1，用底池比例会一律判成「超池大注，后面全跑」，跟注率被压到下限 5%——8 人桌有人开池到 2.5BB，算出来只有 **2.30 人**看到摊牌，J8s 的胜率被抬到 **42%**（真实值约 16%）。

娱乐局的系数是按牌桌实测口径定的（8 人桌 1/2 盲注）：

| 他加到 | 实测 | 模型 |
|---|---|---|
| 5（2.5BB） | 全跟 | 7.7 人 |
| 10（5BB） | 约 5 人 | 4.9 人 |
| 20（10BB） | 3~4 人 | 3.4 人 |

### 4.3 对手范围（`activePctl`）

```
范围 = 基础宽度 × 街次系数 × 下注尺度系数
```

**基础宽度**（`OPP_LEVELS`）：

| 档位 | 翻牌前 | 翻牌后 |
|---|---|---|
| 娱乐局 | 100%（随机牌） | 前 85% |
| 一般 | 前 55% | 前 70% |
| 老手 | 前 30% | 前 55% |

**街次系数**（同样大小的注，越往后越有分量）：

| | 翻牌 | 转牌 | 河牌 |
|---|---|---|---|
| 娱乐局 | ×1 | ×0.8 | ×0.6 |
| 一般 / 老手 | ×1 | ×0.92 | ×0.85 |

**下注尺度系数**（娱乐局按牌桌实测口径重做）：

```
娱乐局：0.291 ÷ 比例^0.703          （比例 = 要跟 ÷ 底池）
一般/老手：clamp(1.05 − 0.8×比例, 0.65, 1)
```

娱乐局翻牌后的最终范围：

| 对手下注 | 翻牌 | 转牌 | 河牌 |
|---|---|---|---|
| ¼ 池 | 前 65% | 前 52% | 前 39% |
| ½ 池 | 前 40% | 前 32% | 前 24% |
| 满池 | 前 25% | 前 20% | 前 15% |
| 2 倍池 | 前 15% | 前 12% | 前 9% |
| 4 倍池 | 前 9% | 前 7% | 前 6% |

> 原来的公式下限是 0.65，**半池就撞到下限**——半池、满池、2 倍池、4 倍池得到的对手范围一模一样。等于「超池注不携带任何信息」，对手可以用超池注价值最大化而不被察觉。这是静态分析列出的头号可剥削点。

**翻牌前面对加注时的娱乐局曲线**（同样是实测口径，27o 都能跟 5 进来）：

| 他加到 | 对手范围 |
|---|---|
| 5（2.5BB） | 前 70% |
| 10（5BB） | 前 50% |
| 20（10BB） | 前 30% |
| 50（25BB） | 前 15% |

四点之间按 **对数插值**——加注每翻一倍，范围收窄的幅度才是恒定的。

**翻牌前无人加注时范围恒为 100%**：大家都还没投钱，范围本来就是随机的，这时收窄反而错。

**「被加注」封顶（v62）**

界面上「要跟」那行下面有个 **被加注** 的小按钮。打开它，对手范围直接封顶：

| 档位 | 封顶 |
|---|---|
| 娱乐局 | 前 12% |
| 一般 | 前 9% |
| 老手 | 前 6% |

这是整套算法里唯一一个**光看数字推不出来、只能由你告诉它**的信息。同样是「要跟 30」：

- 他主动下注 30 —— 范围可以很宽
- 他把我的 10 加到 30 —— 范围窄得多

底池和要跟这两个数字在这两种情况下完全一样，算法分不出来。而这个差别是致命的（见 §10）。

所以这里不是打个折，是**封顶**：加注这个动作本身就把范围钉死了，底池多大、对手是不是跟注站，都改不了这一点。取封顶而非乘系数，正是因为上一版用底池膨胀当代理失败的教训（§9）——乘系数会被跟注站污染，封顶不会。

按顶对 AK 在 K83 上面对 60 / 底池 100 举例：

| 档位 | 他主动下注 | 被加注 |
|---|---|---|
| 娱乐局 | 对手前 35%，胜率 78% → 加注 | 对手前 12%，胜率 70% → 加注 |
| 一般 | 对手前 45%，胜率 82% → 加注 | 对手前 9%，胜率 63% → 加注 |
| 老手 | 对手前 36%，胜率 78% → 加注 | 对手前 6%，胜率 53% → **跟注** |

第二对 KQ 在 AQ77 上则从「跟注」变成「弃牌」，而中三条不受影响照样加注——坚果牌不在乎对手范围多窄。

**换街和新一局都会自动清掉这个标记**，免得一路带着错下去。没人下注时按钮置灰。

娱乐局封得比老手局松，是因为娱乐玩家真会拿着听牌和中对乱加。老手那档收得最紧，是**「等效宽度」而不是字面上的加注范围**：老手的加注范围其实更宽，但里面掺了诈唬，平均牌力反而更低；这套百分位筛子表达不了两极化，只能用一个更窄的宽度去近似它。

### 4.4 有效底池（`potNow`）

```
有效底池 = 原底池 + (本轮已投钱的人数 + 后面预计还会跟的人数) × 要跟
```

后半段必须算——否则就成了「把后面的人当对手却不算他们的钱」的双重悲观。

**筹码不够跟时，底池和跟注额必须用同一个封顶值**：

```js
call   = min(要跟, 我的筹码)
potNow = 原底池 + 人数 × call        ← 用封顶后的数
```

> 原来分子封了顶、分母没封，对手随便报一个巨大的数字就能把「所需胜率」压到接近 0——我只剩 40、底池 100，他推 400，算出来只需 **7.4%** 胜率（真实 22.2%），于是拿 J4o 也全下。这不是模型偏保守，是纯粹的定价错误。

### 4.5 位置兑现系数（`realizeFactor`）

原始胜率一样，有位置能打出更多价值：

| 位置 | 系数 |
|---|---|
| 庄位（永远最后说话） | ×1.07 |
| 后位 | ×1.00 |
| 前位 / 中位 / 小盲 / 大盲 | ×0.93 |

界面上写成「你有 31.4% → 按位置 29.2%」。

## 5. 决策树

### 5.1 翻牌前，无人加注 → 开池决策

不能拿「多人全下的均分份额」当标尺——真实牌局大多数时候大家都弃牌了，你赢的是盲注，而全下均分完全没有弃牌率这回事。正确做法是查**开池范围表**（RFI）：

| 位置 | 6 人及以下 | 7 人及以上 |
|---|---|---|
| 前位 | 前 16% | 前 11% |
| 中位 | 前 21% | 前 16% |
| 后位 | 前 28% | 前 24% |
| 庄位 | 前 45% | 前 42% |
| 小盲 | 前 42% | 前 40% |

```
排位 ≤ 开池范围              → 开池加注到 2.5 倍大盲（小盲位 3 倍）
不够开池，但多人胜率够高      → 便宜跟一手看翻牌（跛入）
排位 ≤ 开池范围 × 1.35       → 边缘，桌子松可以开
其余                        → 弃牌
```

**跛入分支**的门槛是「多人底池胜率 ÷ 均分份额」：前/中位要 ≥1.25 倍，其余位置 ≥1.10 倍，**老手档直接关掉**（对好对手跛入是送钱）。

这一条存在是因为起手牌排位是按单挑胜率排的，会严重低估同花连张在多人底池的价值：**T9s 单挑排前 35%，8 人桌的胜率却比排前 13% 的 KJo 还高。**

**大盲位无人加注** = 免费看翻牌，直接过牌，不存在开不开池的问题。

### 5.2 翻牌前，面对加注 → 查防守范围表

**翻牌前完全不用底池赔率。** 赔率是按对手拿随机牌算的，而敢加注的人范围明显强于随机，算出来会系统性偏乐观。

```
防守阈值 = 基础表 × 档位系数 × 加注尺寸系数
```

**基础表**（`DEFEND`）：

| 位置 | 再加注 | 跟注 |
|---|---|---|
| 前位 | 前 3% | 前 10% |
| 中位 | 前 4% | 前 14% |
| 后位 | 前 5% | 前 20% |
| 庄位 | 前 6% | 前 25% |
| 小盲 | 前 4% | 前 18% |
| 大盲 | 前 9% | 前 40% |

**档位系数**（`DEFEND_LEVEL`）：

| 档位 | 再加注 | 跟注 |
|---|---|---|
| 娱乐局 | ×1.2 | ×1.8 |
| 一般 | ×1.0 | ×1.0 |
| 老手 | ×1.0 | ×0.7 |

> 这一层是必须的。原来三档共用同一张表——2.5 倍开池时加注尺寸系数对三档都等于 1，于是娱乐局和老手局的防守宽度**一模一样**。可娱乐局的开池范围是前 70%，对着这种范围 J8s 在庄位当然该进；老手开池是前 20%，同一手牌就该弃。
>
> 跟注档按对手范围宽度缩放，再加注档只动一点点——对松对手多打**价值**反打有用，但**诈唬性**反打在他们身上没有弃牌率，不该跟着放宽。

**加注尺寸系数**（`raiseTier`）：

```
系数 = clamp((2.5 ÷ 加注BB数)^指数, 0.05, 1.6)
指数：娱乐局 0.40 / 一般 0.70 / 老手 0.90
```

连续曲线，不是三个硬台阶——否则加到 4.4BB 和 4.6BB 会掉进完全不同的档，而同一档内加多少又完全不影响判断。

指数按档位走的理由：**「大注 = 强牌」这个推断有多可靠，完全取决于对手是谁。** 娱乐局的人拿 A9o 也能加到 15BB，尺寸几乎不携带信息；老手加到 15BB 那基本就是 AA/KK。

曲线在 2.5BB 两侧都要延伸——原来是 `bb ≤ 2.5 一律取 1`，意味着最小加注（2BB）和标准开池（2.5BB）买到的弃牌率完全一样，那对手当然只用最小加注，成本低 20% 效果相同。

**判定**：

```
排位 ≤ 再加注阈值   → 再加注到（有位置 3 倍 / 没位置 4 倍）他加的数
排位 ≤ 跟注阈值     → 跟注
其余               → 弃牌
```

同一手 J8s（对加注范围前 30.6%）面对加到 5 的完整分化：

| 位置 | 娱乐局 | 一般 | 老手 |
|---|---|---|---|
| 庄位 | 45% → **跟注** | 25% → 弃 | 17.5% → 弃 |
| 后位 | 36% → **跟注** | 20% → 弃 | 14% → 弃 |
| 中位 | 25% → 弃 | 14% → 弃 | 10% → 弃 |
| 小盲 | 32% → **跟注** | 18% → 弃 | 13% → 弃 |
| 大盲 | 72% → **跟注** | 40% → **跟注** | 28% → 弃 |

### 5.3 翻牌后，无人下注

```
均分份额 = 1 ÷ 摊牌人数
折算胜率 ÷ 均分份额 ≥ 2   或  折算胜率 ≥ 70%   → 下 ¾ 池
                    ≥ 1.3 或  折算胜率 ≥ 55%   → 下 ½ 池
其余                                          → 过牌
```

> 那条**绝对胜率通道**是补丁。「均分份额」这把标尺在人少时会失效：单挑时均分份额是 50%，要下 ¾ 池得胜率 ≥ 100%，而没位置时胜率还要再乘 0.93，天花板只有 93%——**拿着坚果也只会下半池**，数学上永远达不到。加注门槛同理要 86% 的原始胜率。人多时比例那条更容易先满足，不受影响。

### 5.4 翻牌后，面对下注

```
所需胜率 = 要跟 ÷ (有效底池 + 要跟)
优势     = 按位置折算的胜率 − 所需胜率

优势 < −2%                                    → 弃牌
−2% ≤ 优势 < 2%                               → 临界，看位置和对手（按跟注处理）
优势 ≥ 15% 且（折算胜率 ≥ 1.6×均分 或 ≥ 65%）  → 加注到 要跟 + 0.7×(底池+要跟)
其余                                          → 跟注
```

### 5.5 金额取整

牌桌上推的是实体筹码，「加注到 146」没人推得出来，实际也就推 150：

```
< 50  → 取 5 的倍数
≥ 50  → 取 10 的倍数
```

**只对加注和下注取整，跟注不取**——跟多少是对手定的，必须给准数。

任何建议都不能超过手上的筹码，超了就直接说「全下」。

### 7.2 规则机器人对战（`tools/sim-session.mjs`）

完整的 8 人无限注模拟器（含边池、每街封顶四次加注），让 `strategy.js` 真刀真枪打几十万手。盲注 1/2，每人带入 200（100BB），每手结束把盈亏收走再坐回 200——不这么做的话赢家筹码会无限滚雪球，量出来的成了滚雪球效应而不是策略好坏。

```bash
node tools/sim-session.mjs 200000 amateur        # 松被动
node tools/sim-session.mjs 200000 station        # 跟注站
node tools/sim-session.mjs 200000 tag            # 紧凶
node tools/sim-session.mjs 200000 pro            # 会诈唬会弃牌
HERO_LEVEL=loose node tools/sim-session.mjs 50000 amateur   # 指定「对手水平」
```

5 万手的标准误约 ±4.5 BB/100，20 万手约 ±2.2。

**当前实测（v61，每格 20 万手，BB/100 = 每 100 手赢多少个大盲）：**

| 对手风格 | 娱乐局设定 | 一般设定 | 老手设定 |
|---|---|---|---|
| 跟注站（几乎什么都跟，从不施压） | **+785.8** | +776.1 | +721.0 |
| 娱乐玩家（松被动，拿一对就跟到底） | **+307.6** | +297.8 | +266.3 |
| 紧凶 TAG（范围紧、有牌就打、不诈唬） | +81.6 | **+99.7** | +79.5 |
| 高手（范围紧、该弃就弃、会偷鸡） | +81.4 | **+89.5** | +68.7 |

读法：

- **对手越松赚得越多**，跟注站到娱乐玩家到紧凶，收益差一个数量级。
- **档位设对了才最赚**——对娱乐型对手用「娱乐局」设定最优（+785.8 / +307.6），对紧凶和高手用「一般」最优（+99.7 / +89.5）。设错档位每格要付 10~65 BB/100 的代价。
- **对纪律严明的对手优势就薄了**：+80~100 BB/100 看着还行，但那是对规则机器人的数字，现金桌抽水就要吃掉 5~10。

行为画像（娱乐局设定 vs 娱乐玩家，20 万手）：

```

看到翻牌      22.4%
赢下彩池      15.6%
平均彩池      106.9（53.5BB）
```

### 7.3 LLM 对抗（`tools/llm-table.mjs`）

规则机器人不会诈唬、不会调整、不看位置，测不出真正的对抗性漏洞。这个工具让**外部大模型**当对手，和算法真刀真枪打牌：

```bash
node tools/llm-table.mjs init  --hands 300 --seed 777 --state s.json --level normal
node tools/llm-table.mjs step  --state s.json --pending p.txt     # 推进到需要对手决策
node tools/llm-table.mjs apply --state s.json --decisions d.txt   # 喂回决策，继续
node tools/llm-table.mjs report --state s.json
node tools/llm-table.mjs hands --state s.json --from 0 --to 20    # 逐手复盘
```

所有手牌**锁步推进**——同一轮里不同手牌互相独立，几十上百个决策点打成一个包一次问完。不这么做的话 300 手要上千次模型调用，跑不完。筹码跨手保留，输光才补回 100BB。

这一轮实测（3 个 LLM 对手、300 手）查出了 **4 个真 bug**，全部是几十万手机器人对战一次都没暴露过的：

1. 大盲面对最小加注建议「过牌」（`facingBet` 判据错）
2. 对手推超过我筹码时赔率算错（分子封顶、分母没封）
3. 翻牌无人下注时对手范围退化成完全随机牌
4. 人少时下注和加注的门槛数学上不可达

**300 手的完整结果（修复后，4 人桌）：**

| 座位 | 身份 | BB/100 |
|---|---|---|
| 0 | 本算法 | −14.6 |
| 1 | 剥削型（**拿到了全部源码级弱点**） | −51.4 |
| 2 | 松凶 LAG（对算法一无所知） | +29.2 |
| 3 | 稳健 TAG（对算法一无所知） | +36.8 |

两个值得注意的地方：

1. **拿到弱点清单的那个对手输得最惨**，而两个打法很普通的对手小幅赢了算法。也就是说这 −14.6 不是被「源码被研究透了」打出来的，是**任何一个会打的常规对手都能占到的便宜**——牌桌上没人看得到你的源码，所以这反而是好消息。
2. **300 手在统计上说明不了赚赔**：95% 置信区间约 −128 到 +99，把 0 完全罩在里面。

细分数据（300 手）：

| 按位置 | 手数 | BB/100 |
|---|---|---|
| 庄位 | 75 | +140 |
| 小盲 | 75 | +64 |
| 枪口 | 75 | −58 |
| **大盲** | 75 | **−205** |

| 按翻牌前第一个动作 | 手数 | BB/100 |
|---|---|---|
| **加注** | 36 | **+553** |
| 弃牌 | 146 | −54 |
| **跟注** | 41 | **−295** |

「加注赚钱、跟注亏钱」是整份数据里最强的信号，而且和扑克理论一致：面对有攻击性的对手，没位置地冷跟一手牌是公认的漏斗。把 41 手跟注拆开，亏损几乎全部集中在**大盲冷跟别人的加注**（32 手冷跟里 20 手在大盲，净 −220；跛入 9 手 +6 完全不是问题）。那 20 手的结局是 14 手跟进去、翻牌没中、面对持续下注弃牌。

**这个漏洞规则机器人测不出来**：同一个「跟注」动作放回 20 万手机器人对战里是 **+389 BB/100**（紧凶）和 **+366**（高手），因为那些机器人翻牌后弃得太多，跟进去就是白赚。只有会施加真实压力的对手才让「跟注」变成亏损——这正是 LLM 对局唯一不可替代的地方。

### 7.4 1500 手复测（v61）

改完 v57~v61 之后又跑了一轮，这次 **5 桌 × 300 手 = 1500 手**并行，
三个对手都**不知道算法的任何弱点**（紧凶 TAG / 松凶 LAG / 松被动娱乐玩家），
全部设成「娱乐局」档——对应实际使用场景。

| 座位 | 身份 | BB/100 |
|---|---|---|
| 0 | **本算法** | **+54.7** |
| 1 | 紧凶 TAG | +39.4 |
| 2 | 松凶 LAG | +54.5 |
| 3 | 松被动娱乐玩家 | −148.5 |

1500 手的标准误 ±25.8，**95% 区间 [+4, +106] 不含 0** ——这是第一次拿到
统计上站得住的正结果（上一轮 300 手是 −14.6 ± 113，什么都证明不了）。

和上一轮的关键对比：

| | 上轮 300 手（v56） | 本轮 1500 手（v61） |
|---|---|---|
| 总体 | −14.6 | **+54.7** |
| 大盲位 | **−205** | **+97** |
| 翻牌前跟注 | **−295** | **+91** |
| 入池率 VPIP | 29.3% | 48.5% |
| 加注入池 PFR | 12.0% | 20.8% |

**大盲位从 −205 变成 +97、翻牌前跟注从 −295 变成 +91** ——这两处正是
v57 的大盲反打档放宽和 v61 的 `DEFEND_LEVEL` 分档所针对的地方，
改动方向被独立数据证实了。

单桌之间的方差仍然很大（+165 / +93 / +60 / +10 / −55），
这正说明为什么 300 手一桌得不出结论。

**必须说清的口径差异**：本轮桌上有一个被指定打成松被动的娱乐玩家（净 −4455），
+54.7 里有相当一部分是从他身上赢的，不是对等对手之间的纯优势。
这个设定和真实朋友局吻合，但不能外推到全是好手的牌桌。

完整牌局记录留档在 `test/llm-runs/`，改算法后可以拿同一副牌复测。

## 8. 已知局限

**这些数字不要当真去对标实战。**

- **规则机器人比真实的差牌手还差得多**——不会诈唬、不会调整、不看位置、拿到一对就不肯弃牌。对它们的 +300 BB/100 不代表对真人也能赚这么多。
- **真实牌局还有抽水**——现金桌通常 5–10 BB/100，光这一项就能把面对好对手的那点优势吃干净。
- **这套算法从不诈唬，也没有抓偷鸡的概念**。它是个纯粹的「赔率 + 范围」机器：过牌就是真的弱，下注就是真有牌，面对压力纯按赔率决定跟弃。对手只要注意到这一点就能剥削它（它过牌你就偷，它下注你就尊重）。这是设计取舍，不是 bug。
- **它没有记忆**，不会因为某个对手之前诈唬过就调整。
- **300 手的 LLM 对局在统计上说明不了赚赔**。同一套算法、同一种对手，只换随机种子跑 20 次 300 手，结果从 −150 到 +88 都有，跨度 238。要把赢率误差压到 ±10 BB/100 需要约 10 万手。
- **娱乐局那几条曲线是按一张具体的牌桌校准的**，换一张桌子（不同的人、不同的级别）需要重新校准。一般和老手档缺实测数据，走的是通用公式。

## 9. 试过但否掉的改动

每一条都有实测支撑，记在这里省得以后重走。

| 改动 | 结果 | 为什么否掉 |
|---|---|---|
| 「临界」判为弃牌 | 高手 +3.4（原 +6.7）<br>混合桌 +131.6（原 +187.4） | 两边都变差 |
| 25% 频率半诈唬 | 高手 −14.8 | 变差（但机器人不会弃牌，测不准） |
| 30% 频率抓偷鸡 | 高手 −14.7 | 同上 |
| 留一个对手（大盲）不受范围限制 | 高手 −5.8（原 +15.8） | 把刚修正掉的乐观偏差又加回来 |
| **收窄大盲跟注档 40% → 24%** | 基准无害 | **方向反了**：会扔掉 JTs/T9s/98s/K9s/QJo，却留下 A2o~A9o 全套弱 A。根因是 `vsRaise` 是「全下胜率」排位，天然偏爱高牌，不含「后面还要打三条街」的可打性 |
| **用底池膨胀推断「我被加注过」** | 跟注站 +788→+673<br>娱乐 +296→+227<br>紧凶 +102→+44 | 模型上有效（那手 K9s 的转牌从「下注 20」变回「过牌」），但**底池大不一定代表范围强**——跟注站的底池大是因为他拿垃圾也跟。按档位分级、只收窄主动开火那一侧，两种补救都救不回来 |
| **按牌面凶险度收窄范围**（台面配对 ×0.75、三花 ×0.65、四花 ×0.45、三连张 ×0.80） | 4×3 格**全部变差**，平均 **−29.4 BB/100**<br>（20 万手/格，成对种子） | **重复计算**。`oppBoardTop` 本来就是「在这副牌面上排前 X% 的手牌」——三花牌面上的「前 20% 契合度」几乎全是同花。牌面的凶险已经完整地体现在契合度排序里了，再乘一个系数等于把同一件事算两遍。<br>提这条时我的理由是「这条纯看牌面，不受跟注站干扰，之前完全没试过」——理由本身没错，错在没意识到范围筛已经在做这件事 |
| **把娱乐局的翻牌后曲线套到全部档位** | 一般 −16~−26<br>老手 −18~−42 | 那两档的基础范围本来就窄，再乘一遍就极端了（老手 + 2 倍池收到前 9.8%） |

诈唬和抓偷鸡那两行要打个折扣看：这些机器人**不会弃牌也不会偷鸡**，等于只出石头就宣布布没用，测不准。

## 10. 那个「分不清下注和加注」的漏洞（v62 已修）

### 病症

300 手 LLM 对局里最大的两笔亏损（−97 和 −75）是同一个剧本：

```
K9s 在大盲，翻牌 J♥ K♠ Q♦ —— 顶对，9 踢脚
算法算出胜率 70.2% → 下注 5
对手加注到 16 → 算法跟 11        ← 这步其实是对的（3:1 赔率，34% 胜率就够）
转牌 算法又主动下 25             ← 这里
河牌 算法又下 50                 ← 和这里
对手翻出 AK，输 97
```

对上任何一手敢加注的牌（AK / KQ / KJ / QQ / JJ）K9 都是落后的，可它照着 70% 的胜率打了三条街。

1500 手复测后这个剧本的规模才看清楚：**亏 100 筹码以上的 12 手合计 −1853，吃掉了全部毛利的 53%**。逐手把「最后一次主动下注」那个局面拎出来，对着现实中真会跟注的范围重算，10 手里有 5 手**连对手前 30% 的宽松范围都打不过**：

| 局面 | 算法以为 | 对前 30% | 对前 12% | 我的牌型 |
|---|---|---|---|---|
| 大盲 KTo 河牌 | 66% | 32% | 0% | 一对 K |
| 庄位 KTo 河牌 | 58% | 23% | 0% | 两对 A T |
| 大盲 88 转牌 | 57% | 33% | 5% | 两对 8 3 |
| 小盲 Q9s 河牌 | 60% | 40% | 0% | 两对 Q 4 |
| 小盲 KQo 河牌 | 77% | 53% | 0% | 一对 K |

### 两次失败的尝试

**用底池膨胀当代理**（v57 试过，见 §9）：底池大就当作「我被加注过」。模型上有效，但跟注站的底池大是因为他拿垃圾也跟——四种对手全线变差。

**按牌面凶险度收窄**（v62 试过，见 §9）：台面配对、三花、四连张时收紧范围。理由是「纯看牌面，不受跟注站干扰」。4×3 格全部变差，平均 −29.4 BB/100——范围筛本来就是按牌面契合度排序的，等于把同一件事算了两遍。

### 真正的解法：多加一个按钮

两次失败的共同点是**想从数字里推出这个信息**。但这个信息在数字里根本不存在——它只存在于你的眼睛里。

所以 v62 加了一个 **被加注** 按钮（用法见「怎么用」，参数见 §4.3）。你在牌桌上一眼就知道对面是主动下注还是加注了你，点一下就行，不增加记忆负担。

**效果**（20 万手/格，成对种子，与不加这条对比）：

| 对手 | 娱乐局 | 一般 | 老手 |
|---|---|---|---|
| 跟注站 | +0.1 | +0.1 | +0.1 |
| 业余 | +1.6 | +5.0 | +0.1 |
| 紧凶 | +2.7 | **+10.2** | +6.2 |
| 职业 | +3.3 | **+8.1** | +3.8 |

**12 格全部为正，平均 +3.5 BB/100。** 收益集中在紧凶和职业对手身上，对跟注站几乎为零——这正是应该的：跟注站本来就极少加注，这个标记很少亮起；会思考的对手加注时才真的携带信息。

**封顶值怎么定的**：从前 5% 到前 12% 是一段平台（平均 +3.5~+3.7），再松就开始掉。取平台上**最松**的一档 12/9/6%，而不是最紧的。原因是这些规则机器人几乎不诈唬加注，测试量不出「见加注就跑」要付的代价——平台一路平到 5% 的下限，这件事本身就是测试盲区的证据，不该顺着它一路收到底。

**翻牌前也生效但没法测**：模拟器翻牌前走的是预算好的胜率表，不经过范围筛，所以这条在测试里对翻牌前完全无效果（开关翻前生效与否，12 格数字一位不差）。App 里是生效的，牌理上也对——面对再加注，范围本来就该收到前 10% 上下。

## 本地开发

```bash
python3 -m http.server 8777      # Service Worker 需要 http，不能用 file://
open http://localhost:8777/
node tools/make-icons.mjs        # 重新生成图标（需要本机装了 Chrome）
```

改了文件之后**必须**统一升版本号：

```bash
node tools/set-version.mjs v62
```

它会同时改掉 `index.html` 里所有资源的 `?v=` 查询串、`sw.js` 的缓存名和 `app.js` 的显示版本。三者必须完全一致——否则会出现「新 HTML 配旧 JS」，页面直接白掉。

缓存策略也是围绕这点设计的：页面本身走**网络优先**（联网必拿最新 HTML，断网回落缓存），子资源走缓存优先但**按完整 URL 匹配**（不能 `ignoreSearch`，否则 `app.js?v=v8` 会命中旧的 `app.js?v=v7`）。另外 `index.html` 末尾有一段自愈脚本：若 1.8 秒内 `window.__APP_OK` 没被置上，说明初始化失败，会自动清缓存并重载一次。

改了 `strategy.js` 之后的标准流程：

```bash
node test/engine.test.mjs                                    # 引擎没坏
node tools/sim-session.mjs 50000 amateur                     # 决策基准
HERO_LEVEL=loose node tools/sim-session.mjs 50000 station    # 各档位都要看
node tools/set-version.mjs vNN
```

**同种子配对比较**：把改动前的 `strategy.js` 复制到另一个目录，用同一个 `SEED` 各跑一遍再相减——5 万手的标准误是 ±4.5 BB/100，不做配对比较很容易把噪声当成效果。这个坑踩过：曾经手打了一个没实测过的「基准数」，得出「倒退 54 BB/100」的错误结论，配对复测后发现改前改后**完全相同**。
